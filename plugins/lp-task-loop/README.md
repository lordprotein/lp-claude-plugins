# lp-task-loop

Плагин Claude Code: автономный цикл для задачи по коду. Делает, проверяет, ревьюит, ищет изъяны и дорабатывает, пока блокирующих замечаний нет или не кончились итерации. Только правит файлы: не коммитит и не пушит, это закреплено хуком.

| Команда | Что делает |
|---|---|
| `/lp-task-loop:run <задача> [--max N] [--repo <путь>]` | Цикл «реализация → проверка → скептик → ревью → доработка», по умолчанию до 3 итераций |

## Как работает

Цикл работает как workflow (`skills/run/loop.js`): итерации идут в коде скрипта, промежуточные отчёты агентов не попадают в контекст сессии. Если Workflow недоступен, skill ведёт итерации сам по `skills/run/references/manual-loop.md`.

1. Оркестратор формулирует критерии готовности и находит команды проекта (lint, typecheck, тесты, сборка). Если в задаче есть блок `Evidence:` (реальные данные, снятые при воспроизведении бага), хотя бы один критерий формулируется ровно на этих данных, а скептик проверяет код именно с ними, а не с данными из гипотезы плана. Фикс бага без `Evidence:` помечается в отчёте как непроверенный воспроизведением.
2. `implementer` пишет код. На каждой итерации это новый агент: он получает задачу, критерии и замечания прошлой итерации, а изменения видит в рабочей копии. Тесты не трогает: сломанные перечисляет в «Not done», их чинят через `lp-code-test:unit`.
3. `verifier` (haiku) снимает snapshot рабочей копии через временный индекс и гоняет lint, typecheck и тесты по изменённым файлам. Если что-то упало, ревью пропускается, и ошибки сразу идут в доработку.
4. Двухэтапная проверка. Сначала `skeptic` (opus, effort xhigh): пытается доказать, что задача не решена, принимается только замечание с доказательством. Только если у скептика замечаний нет, `reviewer` (через `lp-code-review:review`, если он установлен) смотрит качество кода.
5. Если блокирующих замечаний нет, скептик делает финальный полный проход, и цикл завершается. Иначе начинается следующая итерация. Цикл останавливается по лимиту или если замечания не меняются между итерациями.

Хук плагина запрещает `git commit`, `push`, `checkout`, `switch`, `stash`, `reset`, `rebase`, `add`, `restore` и подобные команды агентам цикла и, пока цикл идёт, основной сессии в этом репозитории (маркер в данных плагина, считается устаревшим через 3 часа). Snapshot с `GIT_INDEX_FILE` разрешён.

Для экономии токенов на итерациях ≥2 ревью смотрит только изменения с прошлой итерации, а скептик перепроверяет только упавшие критерии (перед «готово» всегда полный проход). Агенты возвращают компактные таблицы.

## Установка

```
/plugin marketplace add lordprotein/lp-claude-plugins
/plugin install lp-task-loop@lp-tools
/plugin install lp-code-review@lp-tools   # необязательно, для ревью
```
